# Баннеры нового главного экрана — 19.10.2026

Реализован первый вариант из выбранных макетов: светлая шапка, постер слева, заголовок и два действия справа, четыре плашки снизу. На телефоне текст и действия идут перед постером.

## Управление

В CRM: **Админка → Баннеры**, маршрут `/admin/banners` (при установке CRM в подпапку — под её базовым URL).

1. Нажать «Новый баннер». По умолчанию выбран новый формат Hero 1:1.
2. Загрузить JPG, PNG или WebP: квадрат, минимум 600×600, до 5 МБ. Рекомендуется 1200×1200. Текст и иллюстрация находятся в одном файле. Полосы переключения рисует сайт.
3. При необходимости добавить отдельное квадратное мобильное изображение, ссылку и alt-текст.
4. Указать порядок, активность и период показа. Даты отображаются в часовом поясе браузера, передаются в UTC; пустые поля снимают ограничения.
5. Сохранить и обновить главную страницу сайта. API требует повторной проверки кэша, поэтому новые записи доступны без ожидания прежних пяти минут.

Готовый комплект: `public/assets/hero/2026-10-19/` — три WebP 1254×1254 про прибыль, остатки и задачи команды; архив `sellico-hero-banners.zip` включает файлы, памятку и значения полей. Исходные PNG и промпты сохранены в `asset-sources/hero/2026-10-19/`.

Если нет подходящих активных записей, API недоступно или все изображения повреждены, херо показывает встроенный набор из трёх новых баннеров. Если недоступны и все три файла набора, остаётся исходный резервный постер. При одном баннере показана одна полоса; при нескольких доступны выбор слайда, стрелки и пауза. Автоматическая смена через 6 секунд приостанавливается при наведении, фокусе и скрытии вкладки. При reduced motion смена только ручная.

Во вкладке **«Главный экран»** показаны только квадратные hero-баннеры: на десктопе три карточки с превью, редактированием и переключателем видимости. Старые широкие баннеры остаются в базе с форматом `strip` и вынесены во вкладку **«Старые баннеры»**; в квадратный блок они не попадают. Для перевода старой записи выбрать Hero и загрузить новый квадратный файл; старую мобильную версию заменить или удалить.

## Контракт

- Существующие admin CRUD: GET/POST `/api/admin/promo-banners`, POST/DELETE `/api/admin/promo-banners/{id}`. Доступ администратора сохранён.
- Новое поле `format`: `hero` или `strip`.
- Новая публичная выдача: GET `/api/public/promo-banners?format=hero`.
- Без параметра формат остаётся `strip`, чтобы старый лендинг продолжал работать при поэтапном обновлении.
- Публичная выдача содержит id, format, image, image_mobile, alt, link; фильтрует активность и расписание, сортирует по sort_order, затем id по убыванию.
- Загруженные hero оптимизируются до 1600 px (основной) и 1200 px (мобильный) без изменения пропорций.
- При ошибке записи сохраняются прежняя запись и файлы. Старые изображения удаляются после успешного сохранения новых.

- Laravel API: `/Volumes/SP PX10/ОСНОВНОЙ БЭК/placesales_api`.

Для новой установки обновить обработчики API, модель, два новых файла миграций, `database/seeders/HeroPromoBannerSeeder.php` и комплект `resources/promo-banners/2026-10-19/`. Применить только миграции этого изменения и установить баннеры в рабочую базу:

```bash
php artisan migrate --path=database/migrations/2026_10_19_120000_add_format_to_promo_banners_table.php --force
php artisan migrate --path=database/migrations/2026_10_19_121000_add_preset_key_to_promo_banners_table.php --force
php artisan db:seed --class=HeroPromoBannerSeeder --force
```

Seeder нужно выполнять от пользователя, имеющего право записи в публичное хранилище. Затем опубликовать CRM и лендинг. Установщик копирует три WebP в публичное хранилище и создаёт три обычные активные записи CMS с порядком 10/20/30 и заданными ссылками. Они видны в admin API и публичной выдаче hero.

`preset_key` — внутренний уникальный ключ установщика. Повторная явная установка добавляет отсутствующие записи, сохраняя ранее изменённые заголовки, картинки, расписание и активность. Установщик не запускается при GET-запросах или каждом открытии страницы. После первой установки его не нужно добавлять в каждый дальнейший деплой: удалённые пользователем баннеры не должны автоматически восстанавливаться.

Старые записи сохраняются. При откате клиентов поля format/preset_key и новые записи оставлять до отката использующего их API. На сервере есть другие локальные изменения; выкладывать весь локальный backend или CRM поверх сервера без выделения релизного набора нельзя.
